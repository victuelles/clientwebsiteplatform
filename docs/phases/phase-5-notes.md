## Decisions and deviations

- **Manifest split in two files.** Browser code needs the manifest (reserved slugs in the page dialogs, the link picker, the permission matrix), but feed providers, data summaries, and health checks run on the server. So `module.ts` holds the data and `module.server.ts` (server-only, optional) holds the functions. Together they carry every field the brief lists. `sectionTypes` holds the section definitions themselves (the registry derives keys from them), because core may not import module folders to find them. `feeds` declares feed keys in the manifest so the client-safe side knows which modules provide feeds.
- **Admin pages live at `/admin/m/[key]`**: one dynamic placeholder route. A module's phase adds a static `m/<key>/` route that takes precedence. The Phase 2 placeholder hrefs (`/admin/blog`, …) are gone.
- **`modules` is now function-only.** The super admin's direct UPDATE policy was dropped, so the dependency rules can't be bypassed. Anon can read only `key`, `enabled`, and `settings`. Test 02 was updated.
- **`set_module_enabled` raises errcode 55000** for dependency refusals, and `protectedAction` now passes 55000 messages through. Messages name the blocking modules.
- **Module settings can be saved while the module is off**, so a module can be configured before it's turned on. Module data stays read-only while off.
- **Directory, inventory, CRM, and booking don't use `publish`**. Blog, galleries, shop, and email marketing use all five actions. The permission matrix shows "–" for unused actions and drops old grants for them on the next save.
- **"Orders" and "bookings" are no longer reserved slugs.** Reserved paths now come only from `publicRoutes`; account pages live under `/account`, which is already reserved.
- **Account area reads module state per request** (from the access context), like the admin. The public site reads the cached state, which the switch action expires.
- **The e2e server never has integration keys.** `playwright.config.ts` blanks them, overriding `.env.local`, so local runs match CI. The brief asks for "Stripe missing → shop switch disabled" and "enabling shop with test Stripe keys shows My orders" in one run, which one server can't do. The second test therefore turns the shop on through `set_module_enabled` as the super admin, which checks dependencies but not env keys. The same applies to email marketing in the CRM dependency test.
- **The brief's step 9 says "Write docs/phases/phase-5.md"**, which is the brief itself. CLAUDE.md says never to overwrite a brief, so these notes are `phase-5-notes.md`.
- **Heading rule:** sections whose module is off are removed before numbering, so the first shown section still gets the h1.
- Fixed while testing: the enable dialog said "visitors see its public pages" for modules without any.

## Check by hand

- On a deployment with real Stripe, Resend, and Mux keys, open `/admin/modules` and confirm the shop, video gallery, and email marketing switches become available.
- Turn the blog on, then off, and watch the live site: the Insights header link and `/blog` should appear and disappear immediately.
- `pnpm module:new <key> --dry-run` for the next module before Phase 6 starts.
- Apply the new migration to a client project with `pnpm db:push`. It drops the direct UPDATE policy on `modules`, so any external script updating that table must use the functions.
